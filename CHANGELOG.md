# Changelog

Changes in openfx-gmic since Natron 2.5.0 (tag `Natron-2.5.0`). Natron 2.6 policy: plug-ins may change their output when their underlying library changes (here G'MIC 2.8.4 → 4.0.8); users who need the old results can keep using Natron 2.5. Changes to the plug-in's own parameters or semantics bump the plug-in's major version. Natron's release notes also list these changes.

## For Natron 2.6

### G'MIC 4.0.8 (was 2.8.4) — #3, #26
- The filters now come from G'MIC 4.0.8 and its community filters: 1202 plug-ins (was 360; 815 in COMMERCIAL builds, see Build). Filters that make no sense in an OpenFX host (batch converters, filters that write files, interactive tools) or that upstream disabled as broken are hidden (#64, #70). Many filters' names, parameters and results changed with G'MIC itself.
- The build downloads only the G'MIC 4.0.8 release tarball (from GitHub, gmic.eu or the MacPorts mirror, sha256-pinned, #18); gmic-community is no longer fetched separately.
- Natron no longer quits on macOS when a G'MIC error happens inside an OpenMP loop, e.g. Smooth [Patch-PCA] on a flat image (#41, #56).
- Bugs found in G'MIC 4.0.7 filters, reported upstream, were patched in the plug-in (hot fixes and CImg patches); G'MIC 4.0.8 has these fixes, and the plug-in's own copies are no longer applied:
  - Z-Time, Exposure Fusion Weight Map, Non-Convolution Edge Extraction, Colorize [Photographs], Smooth [Patch-PCA] (#58, #53);
  - Morphology Painting and Random Pattern Courtepointe, which failed (#67; https://github.com/GreycLab/gmic-community/issues/299, https://github.com/GreycLab/gmic-community/issues/300);
  - Jpr Line Edges (#71), Gleam (#77; https://github.com/GreycLab/gmic-community/issues/301, https://github.com/GreycLab/gmic-community/issues/302);
  - Softlight and Contrast FFT on images with alpha, Mc Flou, Smooth Sketch, Perspective Streak (https://github.com/GreycLab/gmic-community/issues/306, https://github.com/GreycLab/gmic-community/issues/307, https://github.com/GreycLab/gmic-community/issues/309, https://github.com/GreycLab/gmic-community/issues/311), Linify (https://github.com/GreycLab/gmic/issues/223);
  - Colorful Blobs (#79; https://github.com/GreycLab/gmic/issues/222).
- Degrades HSL TSL, Formes Couleurs Variees Dans Image and Motifs Degrades CIE no longer fail with their "Perspective - Param A" shape ("Unknown command 'fx_warp_perspective'"): G'MIC 4.0.8 removed `fx_warp_perspective` (replaced by the new Perspective filter), which they still call; in GPL builds, the plug-in defines it again (as in G'MIC 4.0.7). In COMMERCIAL builds, the "Perspective - Param A" shape of these three filters still fails until upstream fixes https://github.com/GreycLab/gmic-community/issues/312: `fx_warp_perspective` needs `warp_perspective`, which G'MIC 4.0.8 only defines in a community file that these builds leave out.
- Heart Tone and Star Tone, which fail on images that hold at most one tile, are still patched in the plug-in: G'MIC 4.0.8 doesn't fix them (upstream disabled only Halftone Shapes for the same bug, https://github.com/GreycLab/gmic-community/issues/305) (#77).
- Two regressions of CImg 4.0.8's math parser, which G'MIC uses, are patched in the plug-in: `vvar()` with exactly two arguments crashed (a call through a NULL function pointer; patches/cimg-vvar2.sh), and the new `log(1 + x)` → `log1p(x)` optimization rewrote the code that had computed a variable: `y=1+x;log(y);y` and `log(y=x+1);y` gave `log(1 + x)` instead of `1 + x` (also with vectors; patches/cimg-log1p-peephole.sh). No filter of G'MIC 4.0.8 (standard library and community filters) calls `vvar()` or takes `log()` of such a variable.
  Upstream: https://github.com/GreycLab/CImg/issues/501, https://github.com/GreycLab/CImg/issues/502
- `vargkth()` with exactly two arguments, e.g. `vargkth(1,5)`, gave 1 in CImg 4.0.8 (its new 2-argument variant returns a constant 1) instead of 0, the 0-based index that CImg 4.0.7 gave and that `vargkth()` gives with more arguments; patched in the plug-in (patches/cimg-vargkth2.sh). `vargkth(k,NaN)` gives 0 with 2 arguments; the n-argument form gives 1, for NaN input only. No filter of G'MIC 4.0.8 calls `vargkth()`.
  Upstream: https://github.com/GreycLab/CImg/issues/501
- The math parser's older `abs(maxabs(...))` → `absmaxabs(...)` optimization (also in G'MIC 4.0.7; the same for `minabs`) has the same bug, and is patched too (patches/cimg-abs-peephole.sh): with `a=-3;b=1;c=-5`, `m=maxabs(a,b,c);abs(a)` gave 5 instead of 3, and set `m` to 5 instead of -5; `abs(m=maxabs(a,b,c))` also set `m` to 5. No filter of G'MIC 4.0.8 is affected (none takes `abs()` of a variable right after a `maxabs()` or `minabs()` with three or more arguments).
  Upstream: https://github.com/GreycLab/CImg/issues/502
- Filters that upstream disabled as broken after G'MIC 4.0.7 are not in G'MIC 4.0.8: Layer Manipulation, Montage Multi Rows, Halftone Shapes (https://github.com/GreycLab/gmic-community/issues/303, https://github.com/GreycLab/gmic-community/issues/304, https://github.com/GreycLab/gmic-community/issues/305), Color Region, Prime Surface, Reverse Engineer Color Curve. Beauty Retouch, disabled then too, is fixed in G'MIC 4.0.8 (https://github.com/GreycLab/gmic-community/issues/308) and available again. G'MIC 4.0.8 also removed Premade Palette, and added Banknote Engraving, Cracked Mud, Lens Flare, Liquid Marble, Local Color Correction and Perspective Water Waves. Intarsia is shown, as in G'MIC-Qt (#206): it writes an HTML page and PNG images into its Output Directory on every render, so set that folder first (empty by default, i.e. the home folder, as in G'MIC-Qt). Filters are hidden only by generic rules, never by name (#204).
- Smooth [Patch-PCA] no longer returns NaN on flat areas: G'MIC 4.0.8 has CImg's eigen fix, which the plug-in applied before (#71, #77).

### Behaviour changes (saved projects may render differently)
- **Perspective** (G'MIC 4.0.8): upstream replaced the filter (`fx_warp_perspective`: X/Y angles, zoom, center, offsets) with a new one of the same name and plug-in identifier (`fx_perspective`: four corner points, interpolation). Saved Perspective nodes load as the new filter: only Boundary, which both have, keeps its value.
- **Menu group in Natron** renamed from "GMIC" to "G'MIC" (e.g. G'MIC/Artistic). Other hosts still show "GMIC" (apostrophes are removed for their plug-in caches). Plug-in identifiers are unchanged, so saved projects load as before.
- **Plug-in version 2.0: Output Layer** (#57). "Output Layer" now counts from the top of the G'MIC image stack (Source = Layer 0, the "Layer -1" input = Layer -1…), as in G'MIC-Qt; before, it counted from the end. Affects filters that return several images (e.g. Channels to Layers now shows R instead of B by default; Fade Layers, Morph Layers, Tiles to Layers show the first result instead of the last) and filters with layer inputs connected. "Merged" and filters with a single result are unchanged. Natron loads nodes saved with version 1.x using 2.0 and lists them in its error log.
- **Layer inputs for more filters** (#22): filters that work on several layers (Stylize, Align Layers, Morph Layers, Pixel Sort, Brushify…) now have Layer -1…-4 inputs; layer inputs are read at the current frame (some filters, e.g. Deconvolve, read them at another frame before) (#40).
- **Nodes with Ignore Alpha on** (#57): the filter now processes all layers at once (multi-input filters work), and `$1`, `$*`… in text parameters are kept as typed. Gray or RGB results whose size changed (frames, rotation, crop…) come out opaque (#66).
- **Premultiplied inputs** (#54) with semi-transparent pixels are unpremultiplied before G'MIC and the result premultiplied back (G'MIC works on straight colours): fewer dark fringes. Pixels with alpha 0 but non-zero colour (additive) lose their colour. Gray or RGB results of another size than the input (frames, rotation, crop…) come out opaque, instead of having their colours multiplied by the misaligned input alpha; this includes uniform upscales, whose semi-transparent edges now stay unpremultiplied (#66).
- **Point parameters**: default positions are no longer mirrored vertically, points are relative to the first input and don't move when zooming or panning (#40); with non-square pixels they now land on the right pixel (e.g. x 192 → 180 at a pixel aspect ratio of 768/720) (#54).
- **Zoomed-out viewer and proxy mode on Natron** (#54) now render at full resolution and downscale, so pixel-sized parameters (radii, sizes) give the same result at every zoom level (slower when zoomed out). Other hosts are unchanged.
- **Filters relying on G'MIC-Qt's preview** (#60) now render: Tupper's Self-Referential Formula, Shear, Array [Random Jumble] by Px, Color Harmonies, Bit-Plane Shuffler, Lavander Binary Map, and others of the same kind.
- **Text parameters are passed as G'MIC-Qt passes them**: double quotes inside a text are now escaped (a text containing one, e.g. G'MIC code, no longer ends the argument early), and newlines are kept instead of becoming spaces (a `#` comment in multi-line code, e.g. Custom Code, ends at its line instead of hiding the rest). Backslashes are still decoded by G'MIC, as in G'MIC-Qt (`\251` is ©, as in Visible Watermark and Quick Copyright; `\n` a newline); a trailing backslash stays literal. File and folder parameters now pass backslashes literally (a Windows path such as `C:\new` no longer gets a newline). The Command of the generic node still turns newlines into spaces.
- **Removable points** (#79): each point that G'MIC-Qt lets you remove now has an "<point> Enabled" checkbox after it. When the checkbox is off, the filter gets the point as removed (nan,nan) and its handle is disabled. Points that G'MIC-Qt shows removed at first are off by default, so saved projects with these filters now render without them, also where the user had moved them: e.g. Colorful Blobs (blobs 4–12), Gradient [Poles] (points #4–#7), Heightfield Warp (light), Symmetrize (point 2), Warp [RBF], Fluffy Cloud, Symmetric 2D Shape, 3D Mesh, ABN Filigrees and Hitomezashi. Turn a checkbox on to get the point back.
- **Colorful Blobs** (#79): the Radius points now set the blobs' radii. Before, they were ignored outside G'MIC-Qt (fixed in G'MIC 4.0.8, patched in the plug-in before).
- **G'MIC errors** (#39) now fail the render with a message on the node, instead of producing garbage.
- **Output** (#37) is always RGBA, also for an alpha-only input.
- **Locale** (#59): parameter defaults and numbers in G'MIC commands no longer depend on the system locale (under e.g. a French locale, defaults, seeds and sizes could be wrong). The "Fixed (Inplace)" Resize Mode behaves like "Dynamic" (as it always did in practice).
- **Plug-in version 2.0: colour parameters** (#178). Colours without alpha in G'MIC (672 of the 1010 `color()` parameters) are RGB instead of RGBA, as in G'MIC-Qt; their alpha was never passed to G'MIC. Saved projects keep the RGB values, animation and expressions; the alpha is dropped (a link to it, e.g. in a cloned node, is reported when Natron loads the project, until it is saved again; Python `getValue(3)` and expressions reading the alpha give 0). Colours are passed to G'MIC as before (unclamped, so HDR and negative values still pass through).
- **What G'MIC receives at run time follows G'MIC-Qt** (#206):
  - The variables `_host` (`ofx`), `_input_layers`, `_output_mode` and `_output_messages` are set on every run, as in G'MIC-Qt (`_host` was set for preview runs only). `_output_mode` is 0 for Output Layer "Merged" and 1 for "Layer -k" and "Frame": 14 commands of G'MIC 4.0.8 read it, so in these two modes some filters now return fewer results or other ones (e.g. only the first one, or without an extra layer), as G'MIC-Qt's "New Layer(s)" output mode.
  - An empty folder parameter is the home folder, as in G'MIC-Qt (it was the host's working folder, `./`): Intarsia and Valeur Moyenne LCH, which write files on every render, now write them into the home folder by default, and the filters that save a file on request (Ascii Art, Pack, CLUT from After Before Layers…) save it there.
  - The input images are named `pos(0,0),name(<clip>)` (e.g. `name(Source)`, `name(Layer -1)`), as G'MIC-Qt names its layers, instead of `input0`, `input1`…: filters that read the layer name (`gui_layer_name`) get the clip's name.
  - A result with more than 4 channels fails the render ("The image produced by G'MIC has N channels (should be at most 4)."), as in G'MIC-Qt, instead of being cut to its first 4 channels.
  - Log Verbosity's Level 3 is G'MIC's `v 3`, G'MIC-Qt's "very verbose" level (was `v 2`), and its empty 5th option (`v 3`) is gone; a node saved with that option still gets `v 3`.
- **About G'MIC** (#206): the pages of G'MIC's About folder are plug-ins of their own, as in G'MIC-Qt, instead of one "About G'MIC" plug-in that showed all their notes, drew Gmicky with the first checkbox of Download External Data as its mascot choice, and ignored the Mascot Image choice. About G'MIC keeps its identifier: it now shows only its own notes and passes Source through, so saved About G'MIC nodes render Source and lose the values of the other pages' parameters. Gmicky Roddy, Privacy Notice, Release Notes and Tribute to Sébastien are new plug-ins. Filters whose commands write files into G'MIC's folders, or at a path that a command computes, are hidden by a generic rule (a rule on the files written, not on network access): it hides the pages that download or post (Download External Data, Send Feedback, What's New?), and SVG Symetries A and SVG TSP, which write their result into G'MIC's folder as Layers To PNG (already hidden) does. A filter whose commands are both `_none_` or empty passes Source through; one with an empty main command ran a hidden "-blur 2" before. `_none_` only counts as the whole command, as in G'MIC-Qt.

### New
- Renders can be aborted while G'MIC runs (#46, #56).
- Renders running at once start fewer threads (#188): each render uses the larger of the number of threads that the host gives (Natron: those its other renders leave free) and a fair share (the hardware threads divided by the G'MIC renders running in the process), at most the hardware threads. Natron's multithreading off (render threads -1), whose count is 1, thus no longer limits G'MIC to one thread. A filter that uses G'MIC's `parallel` command goes back to all the CPUs after it. `OMP_NUM_THREADS` still sets a fixed number. Results with random numbers depend on the number of threads: set `OMP_NUM_THREADS` to keep them fixed.
- Render progress (#177): the filters that report their progress to G'MIC (its `progress` command, e.g. Upscale [CNN2x], Inpaint [Multi-Scale], Spline Spirograph; most filters don't) show it in the host's progress bar, e.g. Natron's Progress panel for long renders.
- Layer Times (#63, #70): filters with layer inputs get a "Layer Times" group:
  - "Layer -1 Time Offset" to "Layer -4 Time Offset" (frames, default 0) fetch each layer input at the render time plus its offset;
  - "Layers from Source" (0 to 4) takes Layer -1 to Layer -N from Source instead of their own inputs, so a single clip gives a window of frames. Raising it sets the Layer -k offsets still at 0 to -k.
  - The six filters that treat their layers as frames (Fade Layers, Morph Layers, Z-Time, Align Layers, Blend Median, Blend Average All) have this group open and a note in their help. With the defaults, renders are unchanged.
- Output Layer "Frame" (#65): filters that make several frames in one run (Fade Layers, Morph Layers, Tiles to Layers, Spline Spirograph's Number of Output Frames…) play their results over the timeline, result *k* at frame *k* from the start of Source, looping. The node's frame range is still Source's: for a still image, extend it upstream (e.g. with a FrameRange node).
  - The results (up to 1024) are kept in memory, shared by the nodes and render clones with the same inputs and parameters (1/8 of the physical memory, 1 to 4 GiB, leaving room for the host's own cache; `OFX_GMIC_FRAME_CACHE_MB` overrides it, 0 disables it: a decimal number of MB ≥ 0, with `.` as decimal point whatever the locale and an optional exponent, surrounding whitespace allowed; a sign, `inf`, `nan`, hexadecimal, other text or an overflow give the default, with a note on stderr). A still input costs one G'MIC run for the whole sequence, also when several threads or render clones render its frames at once (they wait for the run already going). Changing a parameter or an input runs the filter again; results too large to keep run the filter on every frame.
  - Each run computes all N results before one is picked or kept, so its peak memory is N full-size frames whatever the cache budget (e.g. 512 HD frames, about 17 GB): the filter's own frame count parameter limits it.
- Users can disable plug-ins (#157): the bundle's `Contents/Resources/gmic_ofx_plugins.txt` lists every plug-in identifier; a copy in `~/.config/gmic/` (Windows: `%APPDATA%/gmic/`) with lines commented out (`# eu.gmic.AddGrain`; if an identifier is on several lines, the last one wins) disables those plug-ins. After a change (or a change to `gmic_ofx.gmic`), restart the host and clear its plug-in cache, which is required: Natron: Cache > Clear Plug-ins Load Cache, or `--clear-openfx-cache`; with a stale cache, nodes may silently become other filters. A disabled plug-in is not registered: Natron reports that it can't load the plug-in and doesn't create the node, so re-enable it before opening and saving such projects. See README, "Choosing the plug-ins".
  - The list may have CR-only (classic Mac) line endings and be UTF-16 with a byte-order mark (Windows PowerShell 5's `>`) (such files disabled nothing); when a user's list is read, one stderr line reports how many plug-ins it disables and the disabled identifiers that match no plug-in (#171).
- G'MIC's filter update file (#180), opt-in: with `OFX_GMIC_UPDATE_FILE=1`, the plug-in reads `update408.gmic` from G'MIC's folder (where G'MIC-Qt's filter updates and `gmic update` write it: `~/.config/gmic/` by default, `%APPDATA%/gmic/` on Windows, or `$GMIC_PATH`, `$XDG_CONFIG_HOME/gmic/`), so that it gets the filters added or fixed since G'MIC 4.0.8 was released, as G'MIC-Qt does. The plug-in never downloads it; `gmic_ofx.gmic` and `gmic_stdlib.gmic` still come first, and COMMERCIAL builds ignore it. Off by default because G'MIC-Qt rewrites the file on its own (monthly by default), and with a stale host plug-in cache nodes may then become other filters: clear the cache after each update, or copy the file to `gmic_stdlib.gmic` to freeze it. The "[ New Version Available! ]" page that G'MIC puts into the update files of older versions is never a plug-in. See README, "Filters".
- The Preview Type choice and Preview Split point of G'MIC's split preview (in 229 filters with G'MIC 4.0.8) are greyed out unless Preview/Draft Mode is on: only the filter's preview command uses them, so they did nothing in normal renders. Their help says so, and points to Natron's viewer wipe. Renders are unchanged (#184).
- Messages for hosts started from a menu, which show no stderr (#183): if `gmic_ofx_log` exists in `~/.config/gmic/` (Windows: `%APPDATA%/gmic/`), the plug-in appends its messages and G'MIC's (Log Verbosity) to it, as G'MIC-Qt's "log file" output messages do; a file larger than 16 MB is emptied when a host starts. Output Layer "Frame" results that can't be kept (too many or too large, or an empty result) show a warning on the node. See README, "Messages".

### Fixes
- Filters from a user filter file (`~/.config/gmic/gmic_ofx.gmic` or `gmic_stdlib.gmic`) can call the commands that the file defines, as in G'MIC-Qt: they failed with "Unknown command". The file's commands replace the built-in ones of the same name, so a copy of an older `gmic_stdlib.gmic` now runs its own (older) commands instead of G'MIC 4.0.8's. The plug-in's hot fixes still apply to commands that the file copies unchanged from G'MIC 4.0.8; a command that the file defines another way keeps its definition, with a note when the plug-in loads (#168).
- A stack-buffer overflow in G'MIC 4.0.8's `displacement` and `serialize` commands is patched in the plug-in (patches/gmic-argx-overflow.sh): both wrote a short string (`auto-`, `auto`) into a 1-byte empty string on the stack, `displacement` without a guide image and with the default number of scales (Depth Map Reconstruction, on every render; possibly also Morph Layers, Lava Lamp and Transfer Colors [Multi], depending on what ran before in the same G'MIC call), `serialize` with an argument it can't parse. AddressSanitizer reports it; other builds silently overwrote the bytes that follow it on the stack.
  Upstream: https://github.com/GreycLab/gmic/issues/227
- MSVC builds (Windows x64, ARM64, Arm64EC): G'MIC's `input` command no longer reads past the end of an image title it left unterminated when the input values were longer than its 256-byte buffer: with MSVC, CImg's `cimg_snprintf()` called the CRT's `_vsnprintf`, which adds no `'\0'` when it truncates (patches/cimg-msvc-snprintf.sh, #111; upstream: https://github.com/GreycLab/CImg/issues/507). Montage Pappus Chain crashed in about one render in eight on Windows ARM64; on x64 the over-read gave garbage titles without crashing. MinGW builds were not affected.
- FFTW shared with other plug-ins of the host (e.g. openfx-misc's CImg plug-ins, same libfftw3): FFTW's planner is made thread-safe once per process (`fftw_make_planner_thread_safe`), and CImg never calls `fftw_cleanup_threads()`. After each FFT (G'MIC 4.0.7), it freed FFTW's planner and threads while another plug-in could be using them (possible crash with concurrent FFTs). At unload (G'MIC 4.0.8's fix for https://github.com/GreycLab/CImg/issues/500, still open), FFTW's worker threads were still exiting when the host unmapped the plug-in: with FFTW linked statically (Linux), ABN Filigrees crashed after every render in hostDemo (patches/cimg-fftw-no-cleanup-at-unload.sh). FFTW's idle threads and planner are now kept until the process exits. FFTW ≥ 3.3.5 is now required for `FFT=fftw3` builds. `fftw_plan_with_nthreads` stays a process-wide setting (performance only).
- Global Random Seed (#44, #68): random numbers in multithreaded (OpenMP) filters no longer depend on thread scheduling, so for most filters a seed gives the same result for a given number of threads (with one thread, results are as before). Filters using patch matching or G'MIC's `parallel` command, and concurrent renders, can still vary (see the parameter's help).
- Renders where the input and output image bounds differ (e.g. partial render windows) no longer fail with "The image produced by G'MIC has the wrong size" (#40; likely fixes #2, waiting for a retest).
- Wrong parameters or output for many filters: value(), file defaults, choices, colours with alpha, 8-bit flip, gray+alpha (#7, #17, #20, #39).
- Point parameter defaults land inside Source when it is smaller than the project or offset (e.g. Solve Maze failed with "Invalid argument", Spiral Distortion was shifted): when the user connects or changes Source, points still at their default (or reset to it) are set within its region of definition; they don't follow later size changes upstream, e.g. an edited Reformat (#73).
- Text parameters are read as G'MIC-Qt reads them: `text(0,0xFFFFFFFF)` no longer gets the default "0,0xFFFFFFFF" (Kaleido Patterns, Sketchy Ellipses, Seamless Chaotic Pattern and Luminance to Alpha failed or got a wrong value), defaults are unescaped once, as in G'MIC-Qt (the displayed default of `text("C:\\new")` is `C:\new`, without a newline; G'MIC still decodes it when rendering, as with G'MIC-Qt), and `text(1,...)` gives a multi-line text. Filters that need a second input but don't say "layers" get Layer inputs: Fourier Picture Watermark, Save Noise Print, Fast Median Stack, Softlight, Page Curl, Blur by Color, Tiled Form, Depth Map Reconstruction, Lenticular Print, Stereoscopic Image Alignment, Plasma Transition, DOF Manipulation.
- Crashes: more than 32 output images (#37); a render aborted by the user can no longer overflow the output buffer (#56); Spiral Distortion on inputs smaller than the project (CImg fix, in G'MIC 4.0.8, #76).
- Notes, links, choices and other texts no longer have "true" and "false" replaced with "1" and "0" (Upscale [Scale2x]'s note said "useless for 1 colors images"); bool() defaults are read as G'MIC-Qt reads them: true if the value starts with "true" or "1", else false (no built-in filter's default changes) (#120).
- Filter files read from `~/.config/gmic`: a parameter written over several lines no longer gets an extra space after a line ending with `\n` or `\` (#121).
- Filter files read from `~/.config/gmic`: a parameter written over several lines whose closing `)` (or `}`, `]`) starts a line no longer swallows the parameters after it, and a parameter that follows its closing delimiter on the same line is no longer named `), Name` (#132). As in G'MIC-Qt, a value still ends at the first closing delimiter, even inside quotes or nested parentheses: write `note{"a (b) c"}` for a value that contains `)`. The G'MIC standard library built into the plug-in never reaches this code (it has no parameter split over several lines); filters copied from G'MIC 4.0.8's unminified `gmic_stdlib.gmic` to `~/.config/gmic` do.
- Filter files read from `~/.config/gmic`: a value whose `(`, `[` or `{` is never closed (`float(0,1`) no longer loses its last character or, on the last parameter line of an About G'MIC page, takes in the next page's title: it ends with its filter, with a warning (G'MIC-Qt rejects the filter's parameters). A parameter without a name (`=float(1,0,2)`) no longer gets an empty name: it is named "Parameter N" after its position, with a warning, and keeps its argument (G'MIC-Qt shows it without a label) (#169).
- Filter files read from `~/.config/gmic`: a parameter text with `=` but no `(`, `[` or `{` after it no longer makes the host hang while loading the plug-in; it is skipped, as G'MIC-Qt makes no parameter of it. Misreading "About G'MIC" in G'MIC 4.0.8's unminified `gmic_stdlib.gmic` left one behind (#163), so loading that whole file hung (#162).
- Filter files read from `~/.config/gmic`: a comment line (such as a `#@gui` line) that ends with `\` goes on with the next comment line, from after its `#`, as in G'MIC-Qt. G'MIC 4.0.8's unminified `gmic_stdlib.gmic` writes most filters' descriptions and some long parameters this way: their text was cut, and 31 filters lost parameters after it (e.g. Blur [Gaussian], Kuwahara and Rodilius: Channel(s) had 9 of its 47 choices, and Value Action was missing; About G'MIC lost a link). The built-in filters are unchanged (#163).
- Filter files read from `~/.config/gmic`: `choice()` with no label no longer reads outside its list (it could crash the host); it becomes a choice with no options, passing 0 (G'MIC-Qt shows one empty label). A `float()` or `int()` that doesn't have exactly three values (`float(1)`, `float(0,1)`), which G'MIC-Qt rejects, is now a hidden parameter passing 0 (with a warning), instead of making the plug-in load no filters at all, or, for `float(0,1)`, getting the maximum `,1` (#165).
- As in G'MIC-Qt's initial state, parameters marked `_0` after their closing `)`, `}` or `]` are hidden and those marked `_1` are disabled (with a trailing `-`, `+` or `*`, also the notes just before or after them), only in filters that never change the visibility at run time: in G'MIC 4.0.8, 12 parameters of 5 filters, e.g. the "Old …" parameters of Diffusion Limited Aggregation. Points keep their handles, and values are unchanged (#160).
- Link labels are no longer garbled: `link(0,"Label",URL)` showed `Label": : URL`, and `link(Label,URL)` lost the label's last character (Ink Wash) (#122).
- Lowercasing the filter definitions, which contain UTF-8, no longer calls `tolower()` on negative chars (undefined behaviour, an assertion in MSVC debug builds): only ASCII letters change case, whatever the locale (#123).
- Accented and other non-ASCII characters show as written in filter descriptions, notes and menu groups: "Jérôme Boulanger", "Sébastien Fourey", "Cœurs / Hearts", the JéJé group, instead of "Jerome", "S  bastien" or "C&#339;urs". HTML entities (`&#233;`, `&#xE9;`, `&lt;`…) become UTF-8, a `<` or `>` that isn't part of a tag is kept ("a < b"), and hosts other than Natron no longer lose the bytes 0x80–0x9F of UTF-8 characters such as "’" (#124).
- A render without a Source image (or output image) now fails with "No image from Source at frame N" instead of succeeding with an unwritten output, which the host could display or cache; an aborted render still returns quietly (#125).
- Loading the plug-in can no longer terminate the host: the filters are parsed at the first use instead of in a global constructor, an error gives zero plug-ins, and `~/.config/gmic/gmic_ofx.gmic` and `gmic_stdlib.gmic` are read without `tellg()`: for a directory it gave -1 or, on ext4, 2^63−1 (`new char[-1]`, an exception). A directory or an unreadable file is skipped, as a missing one, and the built-in filters are used (#126).
- No exception can reach the host from the plug-in's OFX entry points: an error while listing the plug-ins gives zero plug-ins instead of terminating the host, and the list is built once, so the identifiers the host keeps stay valid (#127, #128). The plug-in no longer reads uninitialised values or a NULL instance pointer when a host's property or clip call fails; it replies with the host's default, or fails the render (#129).
- A filter parameter of a type the plug-in doesn't know (from a newer G'MIC, or in `~/.config/gmic/gmic_ofx.gmic`) no longer aborts debug builds at load: it is hidden and passes 0, as release builds did, with a warning on stderr (#133).
- Float parameters: the value field's step (mouse wheel and arrow keys; in Natron only when the preference "Value increments based on cursor position" is off, and Natron's slider doesn't use it) is a hundredth of the range, and its displayed decimals depend on the range, as in G'MIC-Qt (all used a 0.01 step and 2 decimals; a 0–1 parameter now shows up to 4 decimals, a 0–100 one steps by 1) (#182).

### Build
- Built with C++17 (C++20 for Qt6 builds of Natron) (#33); CI on Linux, macOS (Apple clang, MacPorts) and Windows (#23, #25, #28, #35, #38).
- Windows: the plug-in builds with MSVC (x64), which CI now uses instead of MSYS2 UCRT64 (MSYS2 builds still work, tested weekly with UCRT64): CMake with vcpkg's static zlib and libpng (pinned by `vcpkg.json`) and the static C runtime, and OpenMP (`/openmp`), whose redistributable `vcomp140.dll` is shipped next to GMIC.ofx (found through a manifest embedded into GMIC.ofx), with its notice in Contents/Resources/vcomp140-NOTICE.txt (Microsoft's redistributable, not under the plug-in's licence); Debug builds link it too, not vcomp140d.dll. GMIC.ofx imports only KERNEL32, SHELL32 and VCOMP140; the weekly runs upload the bundle. The plug-in pins `vcomp140.dll` once it renders: hosts that unload the plug-in crashed at exit, when its idle OpenMP threads lost their code.
- Windows on Arm: MSVC builds for ARM64 (`Contents/Win-arm64`, native ARM64 hosts), Arm64EC and Arm64X (one GMIC.ofx with both, `Contents/Win-arm64ec`, for Arm64EC hosts), with OpenMP (the ARM64 `vcomp140.dll` is an Arm64X image). CI builds the ARM64 and Arm64X plug-ins weekly on windows-11-arm, describes them and renders the pr subset with ARM64 and Arm64EC hosts, and merges them with the x64 plug-in into one weekly Windows bundle (`openfx-gmic-windows-msvc`: `Win64`, `Win-arm64ec`, `Win-arm64`).
- CI artifacts are self-contained (bundled libraries) (#62).
- CMake builds the plug-in (also for COMMERCIAL builds), with openfx's `cmake/OpenFX.cmake`; CI builds with CMake, including Rocky Linux 9 (#61, https://github.com/NatronGitHub/Natron/issues/1181). The Makefile is a fallback for Natron's build-plugins.sh (PLUGINS_BUILD_SYSTEM=make); CI checks it with one weekly Linux GPL release build compared with the CMake one (bundle and sources). CMakeLists.txt reads the G'MIC version, checksums and patch list from the Makefile.
- The unmaintained Xcode project (GMIC_OFX/GMIC_OFX.xcodeproj) is removed: CMake generates Xcode and Visual Studio projects (`-G Xcode`, `-G "Visual Studio <n> <year>"`).
- The unmaintained Adobe After Effects and Premiere Pro code (`AE_PLUGIN`, never built, tested or shipped by this repository or Natron) is removed: the plug-in is OpenFX-only.
- The OpenFX glue is ported from hand-written code on the raw OFX C API (Helpers/RFX_OFX_Utils.h) to openfx's C++ Support library (gmic_ofx.cpp), as the other Natron plug-ins: the plug-ins, their parameters and clips, and their renders are unchanged. The Makefile build now compiles the Support library (openfx/Support/Plugins/Makefile.master), and CMake links openfx::Support.
- The string helpers of the original reduxFX code (Helpers/RFX_StringUtils.*) are now Helpers/gmic_string.*, on the C++17 standard library: `std::to_string` for integers, and `std::to_chars` for the numbers of the G'MIC command line, with the same text as before (`%.8g`; a NaN is always `nan`). The plug-ins and their renders are unchanged (#205).
- The parameter model of the original reduxFX code (Helpers/RFX_Parameter.h) is now Helpers/gmic_parameter.h, in namespace `gmic_ofx` (as the parser): `constexpr` constants and `enum class` types instead of macros and plain enums, without the `PAR_*` accessor macros and the angle parameter type that no filter used. The plug-ins and their renders are unchanged (#205).
- The scheduled CI run is weekly (Saturday 03:17 UTC; was nightly), never skipped: the toolchains (package managers, runner images) move even when master doesn't. The Windows bundle artifacts (openfx-gmic-windows-msvc, and openfx-gmic-windows-x64-msvc on pre-release tags) are kept for 14 days.
- The Linux CI artifact (openfx-gmic-linux-release) is now the installed bundle. Every Linux artifact uploaded before (workflow_dispatch and pre-release-tag runs) was the build-tree bundle: its GMIC.ofx had an empty RUNPATH entry, so the loader also searched the current directory. Download a new one if you have an older one.
- COMMERCIAL builds (#74; `make LICENSE=COMMERCIAL`, `cmake -DOFX_LICENSE=COMMERCIAL`), for Natron's COMMERCIAL builds, contain no GPL code: only code compatible with the CeCILL-C option (pocketfft is BSD-3-Clause, some filters CeCILL-B).
  - The standard library keeps only the filters whose licence allows it (815 plug-ins); `gmic_stdlib_commercial.txt` lists what is left out, and why. GPL builds are unchanged.
  - COMMERCIAL builds are no longer CI-tested (no CI job, weekly or release build), and are low priority; the build support stays.
- The bundle ships its licence texts in Contents/Resources (#74): COPYING, CeCILL-C and CeCILL v2.0, plus CeCILL-B in COMMERCIAL builds and pocketfft's licence when it is used.
- Builds with `-Ofast` or `-ffast-math` keep NaN and infinities, which G'MIC needs (`-fno-finite-math-only` is added after the user's flags, also with Intel icx, whose default `-fp-model=fast` has it; `/fp:precise` with MSVC): with `-ffinite-math-only`, G'MIC's `isnan()` and `isinf()` always returned 0 and points removed in Colorful Blobs were drawn. Compiling with `-ffinite-math-only` or `/fp:fast` in effect is an error. Point parameters no longer become NaN (0/0) when the output rectangle is empty.
- The plug-in's two entry points (OfxGetPlugin, OfxGetNumberOfPlugins) are exported with `OfxExport` from openfx's ofxCore.h, instead of a local macro that also refused to build on systems it didn't list (#105).
- CMake 3.21 or newer is required (was 3.16), as openfx's CMake modules now are (https://github.com/NatronGitHub/openfx/pull/196); the build uses the policies of CMake 3.21 to 3.31.
- openfx submodule updated: its HostSupport, Support and API header changes (including one new and one removed ofxNatron.h property, stricter status codes, plug-in read-only param properties on instances, opt-in colour-managed params, OfxExport for every compiler, bug fixes from a C++ Core Guidelines review, and the removal of the Natron cursor extension) don't affect the plug-in, which only writes kOfxParamPropEnabled on param instances (#105). The plug-in now uses the Support library's lazy registration (https://github.com/NatronGitHub/openfx/pull/307), edit blocks begun on the first change (https://github.com/NatronGitHub/openfx/pull/304) and pixel addresses with negative row bytes (https://github.com/NatronGitHub/openfx/pull/280) instead of its own code. hostDemo now sends kOfxActionDestroyInstance before deleting the instance (https://github.com/NatronGitHub/openfx/pull/190), so the render test also covers instance destruction. On Linux, the build-tree GMIC.ofx now has its install RUNPATH (https://github.com/NatronGitHub/openfx/pull/220).
- openfx submodule updated to https://github.com/NatronGitHub/openfx/commit/52fe4b9f73c1a2d89198b17f962e6a3765102657, after its merge of upstream OpenFX 1.5.1 (https://github.com/NatronGitHub/openfx/pull/320; no API or ABI change) and hostDemo's `--multiplane` option (https://github.com/NatronGitHub/openfx/pull/331, not used by the tests): its Support and HostSupport libraries need C++17, so the Makefile build now defaults to `-std=c++17` (none if CXX or CXXFLAGS_EXTRA already has a -std; Makefile.master adds it; it was the compiler's default) and the describe test's host is built with C++17 (was C++11). The Support library's debug log is now `ofxPluginLog.txt` (was `ofxTestLog.txt`), appended to instead of overwritten.
- Hosts that use openfx's HostSupport at this version (https://github.com/NatronGitHub/openfx/pull/318) now detect a stale plug-in cache, instead of using the wrong plug-in: GMIC.ofx's list of plug-ins changes without the binary changing when the user's filter file (`~/.config/gmic/gmic_ofx.gmic` or `gmic_stdlib.gmic`) or G'MIC's update file changes. They then print "stale plug-in cache" and use the plug-in found at another index, or none; clearing the host's OpenFX plug-in cache shows the new list.
- FFTs use pocketfft by default, for every licence, as openfx-misc does (https://github.com/NatronGitHub/openfx-misc/pull/171): pocketfft is BSD-3-Clause and header-only, downloaded at a pinned commit and sha256-checked (`POCKETFFT_HEADER=<path>`, `-DGMIC_POCKETFFT=<path>` for offline builds), so FFTW is no longer a build dependency, and COMMERCIAL builds contain no FFTW (GPL). FFTW is opt-in for GPL builds (`make FFT=fftw3`, `cmake -DFFT=fftw3`; refused for COMMERCIAL builds). Results of FFT-based filters (Fourier Transform, Contrast FFT, Bandpass…) may differ from FFTW builds in the last bits. On Windows, pocketfft is single-threaded (`POCKETFFT_NO_MULTITHREADING`): unloading the plug-in deadlocked when its thread pool joined its threads under the loader lock.
- Linux: GMIC.ofx needs only system libraries (libc, libm, libstdc++, libgcc_s, libgomp), so that one build runs on every distribution (Natron 2.6's baseline is Rocky Linux 9: glibc 2.34, GCC 11). zlib and libpng (and FFTW with `FFT=fftw3`) are linked statically, from static archives built with -fPIC (`.github/workflows/build_static_deps.sh` builds them; `GMIC_STATIC_DEPS=0`, `-DGMIC_STATIC_DEPS=OFF` link the shared libraries, e.g. for distribution packages), and the Makefile no longer links OpenGL. CI checks the libraries that GMIC.ofx needs and reports the symbol versions it requires.
- No libcurl on any system: G'MIC downloads filter data (CLUTs of Color Presets and Simulate Film, CNN networks, sample images) with the system's `curl` command, `/usr/bin/curl` on macOS, `curl.exe` from System32 on Windows (part of Windows 10 1803 and later; then PowerShell), `curl` or `wget` from PATH on Linux, no longer from the host's current directory first. Unlike the old libcurl code, the curl command verifies TLS certificates, so downloads can fail behind a TLS-intercepting proxy. libcurl is no longer a build dependency, and the macOS and Windows bundles no longer ship libcurl and its libraries (OpenSSL, libidn2, libssh2...), nor `LGPL-libraries.txt`, the note on its LGPL dependencies.
- Local patches removed, since G'MIC 4.0.8 has their fixes: gmic-apple-abort.sh (abort support on macOS, #41, https://github.com/GreycLab/gmic/issues/219), cimg-math-macro-overread.sh (https://github.com/GreycLab/CImg/issues/496), cimg-ij-boundary.sh (https://github.com/GreycLab/CImg/issues/498), cimg-symmetric-eigen.sh (https://github.com/GreycLab/gmic/issues/221), cimg-pocketfft.sh (CImg's own `cimg_use_pocketfft`, https://github.com/GreycLab/CImg/pull/497) and cimg-fftw-no-cleanup.sh (CImg 4.0.8 no longer cleans up FFTW after each FFT; its cleanup at unload is removed by patches/cimg-fftw-no-cleanup-at-unload.sh, see Fixes). Only patches/cimg-omp-rand.sh (#44) is left, plus the four math parser patches above, cimg-fftw-no-cleanup-at-unload.sh, patches/gmic-win-thread-stack.sh (below) and patches/gmic-argx-overflow.sh (see Fixes).
- Windows: the threads of G'MIC's `parallel` command, and the plug-in's render thread (which runs G'MIC so that renders can be aborted), have an 8 MiB stack, as on macOS and Linux (patches/gmic-win-thread-stack.sh, https://github.com/GreycLab/gmic/issues/226). They had the host executable's default stack, 1 MiB for programs linked with MSVC (2 MiB with MinGW), which filters such as Vintage Style, Paper Cuts, Morphology Painting or 3D Conversion overflowed (a crash).
